# STK LEO 场景真实联调记录（2026-09-24）

## 1. 目标与边界

本次使用 `STK_LEO_Constellation_20260923_train_v2` 中真实 STKTRACE2 数据，按项目的“STK trace → RFsim IQ 样本时钟 → OAI gNB/UE → OAI 5GC → ext-DN”架构完成静态与动态端到端调试。

本次只验证首次卫星切换前的单星区间，不把结果外推为多卫星切换成功。原始 UE 日志可能包含测试鉴权材料，因此本记录只保留脱敏状态与用户面指标。

## 3. 调试过程与根因

### 3.1 初始故障

在 7614 秒低仰角、关闭噪声以及 7882 秒高仰角三组条件下，结果一致：

- gNB 与 AMF NG Setup 成功；
- UE 能完成下行同步并解码 SIB1/SIB2/SIB19；
- UE 所有 PRACH 尝试均收不到 RAR；
- gNB 没有 PRACH 检测记录；
- 无 RRC、PDU Session 或 `oaitun_ue1`。

因此排除了核心网、认证、下行同步、低仰角和噪声为主要原因，问题定位到上行发射时间。

### 3.2 根因：UE `position0` 与 trace 坐标不一致

OAI `--autonomous-ta` 的服务链路距离读取 UE 配置 `position0`，而不是 STK trace 的 `ue_x/y/z`。旧配置坐标为 `(0, 0, 6377900)`，本场景 UE 坐标为 `(-2176831.540396419, 4387441.71613672, 4071933.940179984)`。

7882 秒处量化结果：

| 输入 | 服务距离 | RTT TA |
|---|---:|---:|
| STK trace UE 坐标 | 2206.084 km | 14.717410 ms |
| 旧 `position0` | 5761.081 km | 38.433797 ms |
| 差值 | 3554.997 km | 23.716388 ms |

UE 因此把 PRACH 多提前约 23.7 ms，完全落出 gNB 接收窗口。复制私有配置并只修正 `position0` 后，在不改变功率、噪声或协议参数的情况下成功完成：

```text
4-Step RA succeeded
NR_RRC_CONNECTED
5G-AKA / Security Mode
PDU Session Establishment Accept
oaitun_ue1 up
```

为防止复发，`prepare_local.py` 现在会在启动前校验 `position0` 与 trace 首行 UE ECEF 坐标，误差超过 1 米就给出明确错
### 3.3 iperf 控制器问题

首次吞吐测试失败于 `/usr/bin/iperf3` 不存在。原实现误以为 `nsenter -n` 会进入 ext-DN 容器文件系统；实际上它只切换网络命名空间，二进制仍从 WSL 宿主机解析。

由于当前 WSL 的 apt 存在与 MongoDB 包有关的未满足依赖，没有执行可能扩大影响的 `apt --fix-broken install`。本次从 ext-DN 临时复制 iperf3 3.9 和所需小型动态库，并让两端使用同一宿主机可见路径。`experiment.py` 已支持：

```bash
export OAI_IPERF3_BIN=/tmp/oai-iperf3/iperf3
export OAI_IPERF3_LIBRARY_PATH=/tmp/oai-iperf3/lib
```

## 4. 真实验证结果

### 4.1 静态模式（rate=0）

- 4-Step RA、RRC、NAS 安全流程、PDU Session：通过
- UE 地址：首次实验为 `10.0.0.2`（脚本实际动态读取，不应硬编码）
- ping 到 ext-DN `192.168.70.135`：10/10，0% 丢包，平均 RTT `92.547 ms`

### 4.2 动态模式（rate=1）

标准命令：

```bash
sudo --preserve-env=OAI_UE_CONFIG,OAI_IPERF3_BIN,OAI_IPERF3_LIBRARY_PATH \
  python3 local_ntn/validate_dynamic.py --tag real-dynamic-fixed-20260924
```

自动验证退出码为 0：

- 动态 PDU 建立：通过
- trace 随 IQ 时钟推进：约从 STK 7882 秒推进到 7958 秒

- 总传播时延约从 `14.717 ms` 变化到 `15.094 ms`
- ping：10/10，0% 丢包，平均 RTT `145.106 ms`
- UE → ext-DN UDP：接收 `99.4 Kbit/s`，0/130 丢包，jitter `36.492 ms`
- ext-DN → UE UDP：接收 `101 Kbit/s`，0/131 丢包，jitter `3.212 ms`

## 6. 尚未验证与后续工作

1. 本次没有跨越 8244 秒首次卫星切换，不能宣称多星切换已验证。
2. blend 轨迹降低了功率突变，但切换位置和速度仍有较大跳变；应先设计真正的 serving-satellite/handover 状态模型。
3. 当前场景 UE 是固定位置。若后续使用移动 UE，仅校验首行 `position0` 不够，需要让 OAI 自主 TA 的 UE 位置随 trace 更新。
4. WSL apt 依赖状态需要单独维护；不要在实验中临时执行可能改变 MongoDB 包集合的自动修复。
