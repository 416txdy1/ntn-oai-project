## 遇到的报错及修正

| 现象 | 原因及处理 |
|---|---|
| setup refresh had errors | 沙箱执行/文件编辑助手初始化失败；通过获得许可的执行入口运行同一个 apply_patch，所有代码编辑仍为补丁 |
| apply_patch 的最后一行报错 | Windows PowerShell 5/bat 多行参数传递问题；改用 PowerShell 7 直接调用补丁入口 |
| rg: command not found | WSL 未装 ripgrep，检查时使用 grep；不影响项目运行 |
| 缺少 /home/kayoko/... | 旧机器硬编码；增加 paths.py，默认当前用户的 OAI 目录 |
| 找不到 flags.make | 当前构建为 Ninja；从 Ninja compdb 提取实际编译参数 |
| sudo: a password is required | 非交互 sudo 无法输入密码；使用可见调试流程中明确的 WSL root 调用，不改密码或 sudoers |
| pipefail: invalid option name | Bash 读取 CRLF 行尾；shell 转 LF，添加 gitattributes |
| debug-session.log 被另一个进程占用 | 编译和测试并发 Tee-Object 写同一文件；拆成两个日志窗口 |
| MySQL ERROR 2002 socket (111) | 刚启动时数据库尚未 ready；后续 healthy 后重试审核成功，未重建数据库 |
| STKInitializationError: Failed to attach... | 没有可附加的活动 STK 12 场景；改进错误提示，真实导出仍待提供场景 |
| Missing prerequisites: stk_trace.csv | 真实轨迹尚未生成；在启动任何 modem 前明确退出 |
| namespace 不存在、容器又退出 | 短 WSL 会话结束后实验环境停止；打开持久 WSL 终端、重新启动容器并建立网络；status 改为友好提示 |
| WSL git diff --check 把 CRLF 大量判为尾部空白 | Windows/WSL 文本转换设置不同；gitattributes text=auto 后检查通过，不批量改无关文件内容 |
| 外部 OAI 整仓库 diff --check 指向旧 compose 第194行空白 | 这是此前已有的 compose 修改；本次未碰此文件，只对本次改动源码另行检查 |
| IQ 测试 unused parameter 编译警告 | 测试桩故意不使用部分回调参数；非错误，数值断言正常执行 |
| WSL localhost proxy/NAT 警告 | 现有 WSL 代理设置提示，未改全局配置；本次本地编译与容器检查不依赖联网下载 |

代码审查额外修正：动态测试的非零返回码传播；旧信道默认可见性不能静音 STKTRACE2；测试强制 -UNDEBUG；本机 PLMN/DNN/切片一致性。
