# NTN 星座无缝业务切换设计

**状态：** 2026 年 9 月 24 日已获得用户同意进入实现阶段。

## 一、设计目标

在现有单小区 OAI 架构中，当 STK/RFsim 轨迹从一颗低轨卫星切换到下一颗卫星时，保持以下状态不变：

- OAI 小区和小区配置；
- UE 的 RNTI；
- NAS 注册状态；
- PDU Session；
- `oaitun_ue1` 接口。

验收目标是跨越两次卫星切换：

```text
OAI_LEO_P01_S06 → OAI_LEO_P01_S05 → OAI_LEO_P01_S04
```

并通过持续 ping 和 UDP iperf 验证业务连续性。

## 二、当前问题和根因

当前轨迹在切换时直接使用下一颗卫星的独立 STK 状态，没有过渡过程。

第一次切换附近的参数变化为：

| 参数 | S06 切换前 | S05 切换后 | 突变量 |
|---|---:|---:|---:|
| 传播时延 | 约 21.605 ms | 约 15.545 ms | 约 6.06 ms |
| 多普勒频移 | 约 -39.55 kHz | 约 +26.67 kHz | 约 66.2 kHz |

这种跳变会使 UE 的 PHY 层失去连续的定时和载波跟踪，因此出现连续：

```text
Error decoding PBCH!
```

当前 UE 日志仍保持 `RRC_CONNECTED`，PDU Session 也没有立即释放，因此主要问题是无线信道参数突变，而不是核心网认证或 PDU Session 被删除。

## 三、拟采用的切换机制

### 1. 建立切换保护区

在旧卫星到达释放门限之前，提前发现下一颗可用卫星，并为两颗卫星建立一个默认 5 秒的 STK 时间保护区。

### 2. 对信道参数进行连续渐变

在保护区内，不再在一个 IQ 秒内直接替换参数，而是对以下参数进行连续插值：

- 传播时延；
- 径向速度和多普勒频移；
- 接收功率；
- C/N。

因此 RFsim 看到的是连续变化的有效信道，避免时延和多普勒突然跳变。

### 3. 保持 OAI 会话不变

切换只改变 RFsim 信道状态，不重新建立小区、不改变 RNTI、不触发 NAS 重新注册，也不重建 PDU Session。`oaitun_ue1` 应只创建一次并持续存在。

### 4. 增加切换阶段日志

调度文件和 OAI 日志增加以下阶段：

- `steady`：稳定连接旧卫星；
- `prepare`：发现并准备下一颗卫星；
- `blend`：旧卫星和新卫星参数渐变；
- `complete`：新卫星成为当前服务卫星。

日志需要输出旧卫星、新卫星、STK 时间、仰角、时延和多普勒。

### 5. 验证业务连续性

长时间测试从第一次切换之前开始，持续覆盖两次切换，同时执行：

- 每秒一次的 ping；
- 与切换时间段重叠的 UDP iperf；
- `oaitun_ue1` 状态监测；
- RRC 和 PDU Session 状态监测。

只有同时满足以下条件，才判定为无缝业务切换：

- PDU Session 只建立一次；
- `oaitun_ue1` 只创建一次；
- UE 不进入 `RRC_IDLE`；
- 两次切换均出现 `handover complete`；
- ping 没有超过保护阈值的连续中断；
- iperf 的丢包率和吞吐变化被完整记录。

## 四、修改范围

### 包含内容

- STK 星座轨迹导出器；
- RFsim `STKTRACE2` 轨迹处理；
- 卫星调度旁路文件；
- gNB/UE 切换日志；
- 离线轨迹测试和长时间业务测试。

### 不包含内容

- 标准 3GPP 多小区 RRC Handover；
- 新增多个 gNB 小区；
- UE 上下文在多个小区之间迁移；
- 修改核心网认证数据库；
- 修改原有单卫星 STK 场景。

## 五、边界说明

该方案实现的是当前 RFsim 单小区模型中的“业务连续性仿真”：通过连续渐变的有效信道保持现有 PDU Session。

它不等同于标准 3GPP NR NTN 多小区 RRC 切换。若后续需要标准切换流程，还需要增加邻区配置、RRC 重配置、目标小区接入和 UE 上下文迁移。

## 六、安全限制

- 不在 STK 轨迹范围外外推卫星状态；
- 非有限或超出 RFsim 样本偏移范围的时延直接拒绝；
- 未提供渐变元数据的旧轨迹仍保持原有行为；
- 原始 UE/gNB 日志只保存在本机，不写入公开文档；
- 不修改用户原来的单卫星场景和配置模板。
