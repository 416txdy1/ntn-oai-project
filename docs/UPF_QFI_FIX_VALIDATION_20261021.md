# UPF 首批下行丢包修复与 MISO 验收（2026-10-21）

## 结论及根因

修复 UPF 从首个 IPv4 上行包学习 QFI 的时序依赖。原 UPF 默认 QFI=5，但本实验 UE 的流为 QFI=1；首批下行包因此被 UE SDAP 丢弃。此问题在原 SISO handover 也存在，不是阵列或 MISO 卷积引入。原诊断见 [逐层证据](STARTUP_DL_QFI_DIAGNOSIS_20261021.md)。

PFCP 抓包进一步确认三次运行的规则相同：建立 ACCESS PDR1，QFI=1；随后建立 CORE PDR2；没有下发 QER。修复优先按下行 PDR 关联的 QER 取有效 QFI，无 QER 时仅接受会话内 ACCESS PDR 唯一且有效的 QFI。缺失、非法或歧义均拒绝，不硬编码1/5，不放宽UE检查。

## 可复现修改

- `upf_patch/0001-control-plane-downlink-qfi.patch` 和 `downlink_qfi.hpp`：替换下行读取会话默认值的路径；上行转发代码不变。
- `scripts/build_upf_qfi.py`、`upf_patch/Dockerfile`：固定 UPF 451c27daa4b38bd03a5cb5b92412743364ff8ae0，在隔离 Docker 中构建；最终仅替换原镜像中的 UPF 程序。
- `scripts/configure_upf_qfi.py`：停机后切换本实验私有 Compose 的镜像，保留备份和原镜像，可回退；原配置模板不修改。
- `scripts/test_upf_qfi.py`、`test_upf_qfi.sh`、`upf_patch/test_downlink_qfi.cpp`：配置隔离和QFI策略测试，已接入 `scripts/test.sh`。
- [手动指南](HANDOVER_MISO_MANUAL.md)新增构建、启用及回退步骤；新初始化的私有环境也必须执行镜像选择器。

## 首包直接证据

短测首20包均为QFI=1，UE全部收到；首个IPv4上行晚于下行首包0.304678秒，所以结果不依赖预热。全程是第二次独立启动，首20包QFI也全部为1，UE全部收到。原镜像本轮对照仍出现5次unmapped QFI=5，修复后的SDAP计数见脱敏证据。

抓包点停止时间不同，不能用整份pcap的总包数直接比较丢包；比较完整覆盖的首20包，并以发送/接收事件为全程交付统计。各抓包点内核丢包计数为0。原始pcap及UE日志仅在.runtime保留，不提交。

## 原实验验收

保持620 IQ秒、epoch=8200、rate=1，使用handover更新的trace和切换表；DL4Tx×1Rx、UL1Tx×4Rx、8计算线程、原随机种子和无线二进制。两次切换完成时刻44、599 IQ秒，窗口前后5秒。参数及无线产物与上次全程逐项比较一致。

业务仍为双向各100000 bit/墙钟秒，1000字节包，理论间隔1000×8/100000=0.08墙钟秒；Ping往返和UDP单向期限均为5墙钟秒，失败比例门限1%，没有剔除首包。最大墙钟运行保护时间不是包期限。
