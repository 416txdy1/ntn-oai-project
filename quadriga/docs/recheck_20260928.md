## 修复及教学说明

外部源文件：`/home/duyaya/OAI/oai-zky-preserve/radio/rfsimulator/simulator.cpp`。

RFsim 已经按 QuaDRiGa 的最大超额时延收集历史 IQ，但清理接收队列时仍使用短 FIR 的 `channel_length`。30.72 Msps 下真实 bundle 需要 33,886 个历史采样点，旧清理逻辑会删除后续卷积仍需访问的数据。常量输入的独立适配器测试不经过队列，无法暴露这个问题。

清理现在使用与输入收集一致的 `qd_channel_history_length()`；可清理阈值不足零时饱和到零，避免负值转换为无符号大数后误删队列。回归示例：当前时间戳 1,000,000、公共偏移 200,000 时，保留边界应为 766,114，而非旧值 799,999。

这是 Bug Fix：修正历史数据丢失，不修改公共 API、核心数据结构、STK/QD 物理参数或文件格式。真实运行的 IQ/误码结果可能不同于旧缺陷版本，旧仿真结果应复跑后再比较。

项目内保留最小补丁 `quadriga/oai/rfsim-history-fix.diff`（由 Python difflib 生成）。原始外部文件备份在 `.planning/2026-09-28-joint-recheck/simulator.cpp.before`。没有覆盖旧 `oai_patch/` 或 `local_ntn/staged/` 历史副本；这些副本不能当作最新 QD 部署源。

测试改动：
- `quadriga/tests/test_rfsim_history.py`：提取并编译实际清理语句，检查长历史、零/负/不足历史时间戳以及无信道模型分支。
- `quadriga/tests/qd_rfsim_adapter_test.c`：支持真实上下行；使用确定性变化 IQ 和独立 Lagrange 基函数，遍历每个快照与中点，并检查前后越界静音。
- `quadriga/README.md`：纠正“尚未接入 OAI”的过时表述。

## 尚未满足的运行条件与模型边界

1. 保存的 audit DL/UL bundle 都是 2 GHz；默认 `run_local.sh` 使用 DL 2.4884 GHz、UL 1.6149 GHz（由载频偏移计算）。适配器会拒绝中心频率不匹配；必须按选定实验载频重新导出，不能只改 manifest 冒充新频率的数据。
2. `experiment.py start` 给两个进程继承同一环境，不能通过单个 `OAI_QD_CHANNEL` 同时传入 DL/UL bundle。现有独立启动方式需给 gNB 设置 uplink bundle，给 UE 设置 downlink bundle；应进一步完善联合启动器后再做全链路测试。
3. 本次构建是 `oai-zky-preserve/cmake_targets/zky_step4/build`，默认启动器硬编码 `cmake_targets/ran_build/build`，后者在该源码目录中不存在。默认 OAI_REPO 还指向另一份 openairinterface5g。不能认为默认启动器会使用此次修复后的二进制。
4. 启动器强制使用 `local_ntn/stk_trace.csv`，不是本次 audit bundle 对应的原始 blend trace；其输入身份必须在启动前对齐，不能绕过 provenance 检查。
5. STK 几何快照间隔 1 s，无法验证高速残余多径 Doppler 的物理准确性。没有改变采样密度、频率、随机种子或原始数据。
6. 既定复系数线性插值不保持中点单位路径功率。本数据中点总功率范围 0.970674447–0.999986012，最差约 -0.129264 dB。这符合当前插值契约，但不能把“快照归一化”解释为“任意时刻都严格单位功率”。改变它属于实验方法变化，本次保留原模型。
7. 适配器测试使用 STK 时间接口替身；STK IQ 测试独立验证实际 STK 路径。尚无真实 gNB/UE/5GC + QD 联合注册、ping、吞吐和长期稳定性验证，不能把两组独立测试当作端到端证明。
